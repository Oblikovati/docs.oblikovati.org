# Design — docs.oblikovati.org Docusaurus tooling

Date: 2026-07-06
Status: Approved
Repo: `docs.oblikovati.org` (github.com/Oblikovati/docs.oblikovati.org)

## Goal

Stand up the tooling to build the Oblikovati documentation website with
Docusaurus 3.10, published as a DigitalOcean App Platform **static site**.
The site is i18n-enabled, highlights Lua fenced code blocks for scripting docs,
and reuses the exact brand theme and logo of `website-oblikovati.org`.

This deliverable is the **buildable scaffold**, not the documentation content.
It must `npm install && npm run build` cleanly (including a non-default locale)
before it is considered done.

## Decisions (locked)

| Topic | Decision |
| --- | --- |
| Docusaurus version | 3.10, classic preset, **plain JS** config (matches sibling `website-oblikovati.org`) |
| Node | 20 (pinned via `.nvmrc`) |
| Site sections | Docs only. Blog disabled (`blog: false`). |
| Docs route | Served at **site root** (`routeBasePath: '/'`) — dedicated docs subdomain, no landing page |
| Versioning | Docs versioning enabled; starts with "current"/Next only |
| i18n | `defaultLocale: 'en'`, locales `['en', 'pt-BR', 'es']`, navbar locale dropdown |
| Lua | `prism.additionalLanguages: ['lua']` — highlighting only, no sample page |
| Theme | Override Infima CSS variables in `src/css/custom.css` + import same Google Fonts; dark-first |
| Deploy | GitHub Actions → DO App Platform static site, CI-triggered via `doctl apps create-deployment` |

## Approaches considered

**Theme integration.** (A, chosen) override Infima `--ifm-*` variables +
import the marketing site's Google Fonts, swizzle only if strictly needed —
lightweight and upgrade-safe. (B) eject a full custom theme — fragile across
upgrades. (C) bolt Tailwind on — fights Infima and duplicates design tokens.

**Deploy.** (A, chosen) GH Actions builds on every PR as a validation gate,
and on push to `main` triggers a DO App Platform static-site deployment via
`doctl apps create-deployment $DO_APP_ID --wait`. (B) sync `build/` to a DO
Space + CDN — a different DO product than the requested "static site app".

## Theme mapping

Palette and typography are taken verbatim from
`website-oblikovati.org/tailwind.config.js` and `src/index.css`:

- Surfaces: `--ifm-background-color: #070b14`, secondary surface `#0b1220`,
  elevated `#111c30`.
- Primary accent: the signal gradient endpoints `#38bdf8` (deep `#0ea5e9`) and
  `#5eead4`; Infima `--ifm-color-primary*` derived from `#38bdf8`.
- Fonts: Albert Sans (headings / `--ifm-heading-font-family`), Newsreader
  (body / `--ifm-font-family-base`), JetBrains Mono
  (`--ifm-font-family-monospace`), imported from Google Fonts exactly as the
  marketing site does.
- `colorMode: { defaultMode: 'dark', respectPrefersColorScheme: false }`.
- Logo + favicons copied from `website-oblikovati.org/public`
  (`logo.svg`, `favicon.svg`, `favicon.ico`, `favicon-16/32`, apple-touch,
  `site.webmanifest`) into `static/img/` so branding is pixel-identical.

## i18n details

- `i18n/pt-BR` and `i18n/es` skeletons created.
- Theme/UI strings generated by `npm run write-translations` (script wired in
  `package.json`); the generated `code.json` per locale is committed.
- Docs content translation folders
  (`i18n/<locale>/docusaurus-plugin-content-docs/current/`) stubbed with a
  placeholder `intro.md` so translators know where pages go.

## Deployment

- **Secrets** (GitHub repo settings): `DIGITALOCEAN_ACCESS_TOKEN`, `DO_APP_ID`.
- `ci.yml`: on pull_request — `npm ci`, `npm run build` (default + `--locale
  pt-BR` smoke) to fail fast on broken builds/broken links.
- `deploy.yml`: on push to `main` — `npm ci`, `npm run build`, then
  `digitalocean/action-doctl` + `doctl apps create-deployment $DO_APP_ID
  --wait`. DO App Platform serves the built static site.
- One-time bootstrap (documented in README): create the App Platform static
  site app in the DO dashboard (or `doctl apps create`) pointing at this repo,
  build command `npm run build`, output dir `build`; capture its id into
  `DO_APP_ID`.

## Verification (definition of done)

1. `npm install` succeeds on Node 20.
2. `npm run build` succeeds (no broken-link errors).
3. `npm run build -- --locale pt-BR` succeeds (i18n wiring proven).
4. `npm run start` serves the themed site locally with the Oblikovati logo,
   dark brand palette, working locale dropdown, and a Lua code block rendering
   with highlighting.

## First content page: Keyboard Shortcuts

The first real page is a **Keyboard Shortcuts** reference driven by the actual
bindings the app ships, not a hand-written table. The bindings are the same
catalog the head's Customize-Keyboard window renders
(`app.Bindings().Catalog()`); we extract them once into committed JSON.

### Extraction — Go dumper (Oblikovati GPL repo)

- New headless command `cmd/keymap-dump/main.go` (GPL-2.0 header, no cgo):
  `NewSession()` + `RegisterStandardCommands(s)`, walk `Bindings().Catalog()`,
  keep only bound actions, and for each classify + group:
  - `kind`: **keyboard** when the chord has a modifier (Ctrl/Alt/Shift) or a
    named non-alpha key (F-keys, Escape, Delete, Enter, …); **alias** when the
    chord is a bare multi-letter word (REC, POL, EL, EX, FF, MI, PT, SPL, SX) —
    a command-window word, not a pressable chord.
  - `group`: derived from the ActionID prefix — `file.*`/`GetStarted.*` → File,
    `Create.*`/`Modify.*` → Feature, `Sketch.*` → Sketch, `View.*`/`view.*` →
    View, `edit.*` → Edit, `tool.*` → Tool.
- A `go test` guards the classifier and asserts the catalog is non-empty and
  every emitted chord round-trips through `types.ParseChord`.
- Output is written to the docs repo at `src/data/keybindings.json`;
  regeneration is a documented manual step, so the docs build stays pure Node
  (no Go dependency).

Ground truth captured on 2026-07-06: **27 bound actions** — 18 keyboard chords
(`Ctrl+N/S/W/Y/Z`, `Shift+A/C/D/E/F/H/L/R`, `F5`, `F6`, `Escape`, `Delete`,
`Enter`) and 9 typed aliases.

Data shape:

```json
{
  "source": "oblikovati.org/app Bindings().Catalog()",
  "shortcuts": [
    { "actionId": "Create.Extrude", "displayName": "Extrude",
      "group": "Feature", "kind": "keyboard",
      "chord": { "key": "E", "shift": true }, "chordText": "Shift+E" },
    { "actionId": "Sketch.Rectangle", "displayName": "Rectangle",
      "group": "Sketch", "kind": "alias",
      "chord": { "key": "REC" }, "chordText": "REC" }
  ]
}
```

### Rendering — KeyboardMap component (docs repo)

- `src/components/KeyboardMap/`
  - `isoLayout.js` — ISO 105-key geometry: rows of `{ label, code, width }`
    with the L-shaped Enter and the extra key by the left Shift.
  - `index.jsx` — inline **SVG ISO keyboard**; for every `kind:"keyboard"`
    shortcut, highlight the base key and its modifier key(s) in the brand
    accent, with a `<title>` tooltip naming the action; a legend; then two
    grouped reference tables — **Keyboard shortcuts** (by File/Sketch/Feature/
    View/Edit/Tool) and **Command-window aliases**.
  - `styles.module.css` — brand key styling; highlight uses the signal gradient
    on the dark surface.
- `docs/reference/keyboard-shortcuts.mdx` — short intro prose + `<KeyboardMap/>`.
  This is the site's first real content page; linked from the sidebar and intro.

The SVG depicts only pressable chords; typed aliases render in their own table
(honest to the binding model). The command window has a fuller vocabulary —
documenting that is out of scope for this page.

## Out of scope

- Translating any content (only locale scaffolding).
- Cutting a numbered docs version (versioning enabled; first cut done later).
- The full command-window alias vocabulary (only the catalog's bound aliases).
